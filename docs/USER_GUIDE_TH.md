# FriendPushScreen 1.0.0 — คู่มือ Portable

สำหรับ Windows x64 ใช้ส่งภาพ H.264 และเสียงที่เลือกให้เพื่อน พร้อมรับภาพ/เสียงกลับผ่านการเชื่อมต่อเดียวกัน

## เปิดใช้งาน

1. แตกไฟล์ friendpushscreen-v1.0.0-portable.zip ลงในโฟลเดอร์ที่เขียนข้อมูลได้
2. เปิด FriendPushScreen.exe โดยเก็บ portable.flag และ DLL ทุกไฟล์ไว้ด้วยกัน
3. โปรแกรมสร้างข้อมูลเฉพาะเครื่องไว้ใน data ข้างโปรแกรม เมื่อเปิดครั้งแรกยังไม่แชร์ภาพและยังไม่เปิดพอร์ตรับการเชื่อมต่อ
4. ถ้าทดสอบสองชุดบนคอมเดียว ให้แตก ZIP ใหม่แยกเป็น A และ B ก่อนเปิดแต่ละชุด เพื่อให้สร้างตัวตนและค่าตั้งค่าคนละชุด

ทดสอบจริงบน Windows 10 22H2 build 19045, Intel Core Ultra 5 245K/iGPU; Windows 11 และเครื่องอื่นยังต้องตรวจการทำงานจริง รุ่นนี้ไม่มีตัวติดตั้งและไม่มีลายเซ็นรับรองไฟล์ EXE

## จับคู่และลบสิทธิ์

- ใน Settings → CONNECTION กด Export Identity ของแต่ละฝั่ง แลกเฉพาะไฟล์สาธารณะ .friendpair
- กด Pair with Friend แล้วเลือกไฟล์ของอีกฝั่ง เปรียบเทียบ SHA-256 เต็มกับเพื่อนผ่านช่องทางที่เชื่อถือได้ก่อนยืนยัน
- โปรแกรมบันทึกเครื่องที่อนุญาตไว้หนึ่งเครื่อง เปิดใหม่ยังจำเครื่องเดิม รายการแสดงรหัสตัวตนจากใบรับรองกับลายนิ้วมือเต็ม
- Remove Paired Device ถอนสิทธิ์ของเครื่องที่บันทึกและตัดการเชื่อมต่อ/ภาพ/เสียงที่ใช้อยู่ เปิดใหม่ยังไม่จับคู่ ต้องยืนยันจับคู่ใหม่ก่อนเชื่อมต่ออีกครั้ง
- ถ้าลบไฟล์สิทธิ์ไม่ได้ โปรแกรมแจ้งข้อผิดพลาดและยังแสดงเครื่องเดิมไว้ โดยหยุดการเชื่อมต่อแล้ว
- ตัวตนและ private key ของเครื่องเราเก็บด้วย Windows DPAPI ไม่อยู่ในไฟล์ .friendpair การย้าย data ไป Windows user หรือเครื่องอื่นไม่ใช่วิธีย้ายตัวตนที่รองรับ

## เชื่อมต่อและแชร์ภาพ

Share Port คือพอร์ตรับของเครื่องเรา ส่วน Host / IP และ Remote Port เป็นปลายทางของเพื่อน ใช้ช่องเดียวกับ localhost, IPv4 LAN, DNS/DDNS หรือ IPv4 Tailscale ตามเส้นทางของ Windows

ใส่เฉพาะชื่อเครื่อง/IP เช่น cdloot.thddns.net โดยแยกพอร์ตเป็น 8997 ใน Remote Port; ไม่ใส่ http:// หรือ :8997 ต่อท้ายชื่อ รองรับชื่อ ASCII/punycode และ IPv4; ยังไม่รองรับ IPv6 ในช่องนี้

ตัวอย่างสองชุดบนคอมเดียว:

| ชุด | Share Port | Host / IP | Remote Port |
|---|---:|---|---:|
| A | 8996 | 127.0.0.1 | 8997 |
| B | 8997 | 127.0.0.1 | 8996 |

1. จับคู่ทั้งสองฝั่งก่อน
2. เลือก Capture Source แล้วกด Start Share ฝั่งที่ส่ง
3. ฝั่งรับกด Connect โดยไม่ต้องเลือกแหล่งภาพของตัวเอง
4. อีกฝั่งสามารถกด Start Share เพื่อส่งภาพกลับได้ เลือก CPU/GPU สำหรับเข้ารหัสและถอดรหัสแยกกันได้
5. Stop Share หยุดภาพที่เราส่ง แต่ยังดูภาพและรับเสียงจากเพื่อนได้; Disconnect หยุด listener, reconnect และการแชร์ของฝั่งเรา
6. Preview เป็นภาพในเครื่อง ส่วนภาพจากเพื่อนมีลำดับการแสดงเหนือกว่า

การเชื่อมต่อจริงใช้ QUIC/TLS ผ่าน UDP ไม่ใช่เว็บ HTTP การเข้าถึงจากนอกเครือข่ายต้องมีเส้นทาง/กฎพอร์ต UDP ที่เหมาะสม โปรแกรมไม่เปลี่ยน firewall หรือ router ให้อัตโนมัติ

## เสียง

เลือก Audio Source เป็น No Audio / System / Device หรือ Application ตามความสามารถของ Windows แล้ว Share เลือก Remote Audio Output เพื่อกำหนดลำโพง/หูฟังที่รับเสียง แถบระดับเสียงและ Mute Remote Audio มีผลเฉพาะเสียงที่รับ

Windows 19045 ที่ทดสอบยังไม่รองรับ Application Audio แบบ process loopback เลือก No Audio ได้โดยไม่หยุดภาพ หากเปิดสองชุดในเครื่องเดียวควรแยกแหล่งเสียงและเอาต์พุตเพื่อป้องกันการวนกลับ โปรแกรมตรวจเส้นทางที่อาจรับเสียงที่ตัวเองกำลังเล่นกลับเข้าไป

## สถานะและหน้าต่างคลีน

Ping เป็นเวลาตอบกลับของ control ในแอป ไม่ใช่ ICMP หรือความหน่วงภาพทางเดียว FPS Send/View คำนวณจากเฟรมที่ส่งเข้าคิว/แสดงผลจริง ค่าจะว่างเมื่อหยุดหรือหลุด

ใน Settings → VIEWER ปิด Show Status Bar เพื่อซ่อนทั้งสถานะและปุ่ม Hide Settings ใช้ Borderless Viewer แล้วกด Tab ปิด Settings เพื่อเหลือภาพล้วน กด Tab อีกครั้งเปิด Settings; F11 เข้าเต็มจอและ Esc ออก ค่าซ่อนแถบถูกบันทึก

## ขอบเขตผลทดสอบ

- สองโฟลเดอร์บนเครื่องเดียวผ่าน localhost, self-LAN และชื่อ DDNS/พอร์ต 8996–8997; DDNS เป็นเส้นทาง NAT loopback ไม่ใช่หลักฐานใช้งาน WAN สองเครื่อง
- self-LAN ประมาณ 60 FPS/ฝั่ง; DDNS ที่ทดสอบประมาณ 30 FPS/ฝั่ง ไม่มี drop/recovery ในรอบสั้นที่ระบุ
- ทดสอบ IP Tailscale ของเครื่องตัวเองเชื่อมต่อได้ แต่มี video recovery 1 ครั้งในรอบที่เก็บไว้ จึงยังไม่ยืนยันความนิ่งระยะยาวหรือ Direct/DERP ระหว่างเครื่อง
- การเปรียบเทียบ QUIC กับ TLS/TCP จากข้อมูลเข้ารหัสชุดเดียวกัน, clock/A-V sync ระหว่างเครื่อง, fault/recovery และการทดสอบ Windows/GPU อื่นยังเปิดอยู่
- อ่านรายงานที่มากับ document.zip หรือใน docs/development/reports ของซอร์สเพื่อดูผลและข้อจำกัดตาม commit จริง

## การอัปเดตและไฟล์ประกอบ

ปิดโปรแกรมก่อนอัปเดต สำรอง data ของแต่ละชุดไว้ต่างหาก แล้วเปลี่ยนเฉพาะไฟล์โปรแกรมจาก ZIP ไม่เอา data ของอีกชุดมาทับ หากต้องการเริ่มตัวตนใหม่ ให้แตก ZIP ใหม่ลงโฟลเดอร์อื่น
